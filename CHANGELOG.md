# Changelog

## Unreleased

- `/usage`: кнопка «🔄 Обновить» рядом с «« Статистика» — заново запрашивает лимиты и пересчитывает экран на месте.
- **Нет токенов → очередь.** Ход упал на лимите подписки, лимите запросов API или пустом балансе API: бот сам отвечает в чат на его языке («⏸ Закончились токены подписки… Отвечу сразу после сброса лимита в 14:20»), записывает новые сообщения и в момент сброса (время берётся из API лимитов подписки или из текста ошибки) отдаёт их сессии одним пакетом, а прерванный ход просит довести. Для лимита запросов API — повтор через 2, 4, 8… мин; для пустого баланса — ждать кнопку «▶️ Продолжить сейчас» (она же в `/menu`, пока пауза идёт).
- Ход, упавший по другой причине (нет входа, ошибка сервера, предел длины ответа, слишком большой запрос), получает понятную подсказку на языке чата вместо одного английского текста.
- **⚡ Окно сразу после сброса** (кнопка в `/usage`, `LIMIT_WARMUP=on`): через минуту после сброса 5-часового окна демон отправляет крошечный запрос `claude -p` на haiku, и новое окно стартует сразу.
- Уведомление о лимите: кнопки «🔄 Обновить» и «✖️ Удалить».
- **Несколько групп топиков (FR-3).** Следующие `/connect_group` подключают дополнительные группы топиков; у каждой — свои папки (`/topics` → «🗂 Группы топиков»), проекты из них получают топик там. `/topics` переключает группы; маршрутизация, разрешения и события топиков работают в любой группе.
- **Папки проектов — по id:** топик → `~/projects/<id группы>-<id топика>`, обычная группа → `~/projects/<id группы>` (без минуса). Переименование топика или одинаковые названия больше не путают папки.
- **Роли (FR-4):** 👑 владелец — всё; 👤 участник (по умолчанию) — пишет в сессии, отвечает на кнопки, жмёт ⏹; 👁 наблюдатель — только читает (его сообщения и нажатия игнорируются). Разрешения, пульт, архив, настройки, приглашение и удаление людей — только владелец; запросы разрешений приходят только ему. Роль меняется кнопкой в `/users`. Сессии видят `user_role` автора, и указания не-владельца не перекрывают указаний владельца.
- **🎤 «В записи нет речи».** Голосовое без слов (выключенный микрофон) больше не уходит в сессию пустым: отправителю приходит «🎤 В записи нет речи — похоже, микрофон был выключен…».
- **Иконка плагина** (`.claude-plugin/icon.png`): `claude plugin validate` проходит без предупреждений.
- **ACCESS.md на 6 языках** (`ACCESS.ru/es/zh/fr/de.md`), README ссылаются на свой язык; в английском — английские подписи кнопок.
- **✍️ Ответ пишется на глазах (FR-1).** В личке ответ растёт в черновике, в группах — в сообщении «⏳ Работаю…». Модель пишет ответ обычным текстом и вызывает `reply` с `use_last_message: true` — бот отправляет написанное, без повторной генерации. Рассуждения до вызовов инструментов в ответ не попадают. Включено по умолчанию, переключатель «✍️ на глазах / 📦 целиком» — в «/menu → ⚙️» для каждого чата. Работает в сессиях, запущенных после обновления (инструкции канала).

## 1.4.0 — 2026-10-29

- **👥 Обычные группы как проекты.** Группа без топиков, разрешённая в access, привязывается к папке проекта из лички владельца: на первое сообщение (или на добавление бота) приходит карточка «📁 Новый проект / 📂 Выбрать проект / 🚫 Не проект». Сессия проекта запускается по требованию, отвечает прямо в группу и показывает там прогресс; до привязки сообщения ждут в очереди. Управление — из лички: карточка сессии («👥 Отвязать группу»), «/menu → 👥 Группы». Запросы разрешений — только владельцу. Напоминания, `/macro`, `/event`, CI работают и в группах. В неразрешённой группе бот молчит и подсказывает владельцу команду `access group add`.
- `/help` и описание `/menu` в меню команд Telegram упоминают группы; README (6 языков), ACCESS.md, ТЗ §5.3e.

## 1.3.0 — 2026-10-29

- **✅ Подтвердить запуск** — кнопка в каждом сообщении о запуске сессии (бот, сторож, приглашение) и в «👁 Экране», когда на нём запрос development channels. Бот нажимает, только если видит именно этот экран Claude Code, и выбирает «I am using this for local development» по положению ❯; на любом другом вопросе (например, о доверии папке) ничего не нажимается.
- **⏳ Напоминание о неподтверждённом запуске:** если запущенная сессия (по сообщению, приглашению, сторожу, топику) не подключилась за `LAUNCH_REMIND_SEC` (180 с) и ещё раз через 5×, владелец получает «⏳ Сессия … ждёт подтверждения запуска» с «✅ Подтвердить запуск»; приглашённый пользователь — что его сессию подтверждают. Раньше новый пользователь видел только «ждите», а сессия стояла на экране каналов.
- **▶️ Живой экран:** «👁 Экран» обновляется сам каждые 4 с в течение минуты, «⏸» — остановить.
- **/server: 📜 логи и ♻️ перезапуск демона.** Последние 40 строк лога (секреты скрыты); перезапуск после подтверждения, `.env` перечитывается, новый демон дописывает в то же сообщение время перезапуска, pid и число подключившихся сессий.
- **🕘 Прошлые разговоры** в карточке сессии: последние 8 разговоров папки с датой, размером и первой фразой; выбранный продолжается `/resume <id>` в той же сессии — без перезапуска и подтверждения.
- **📌 Всегда в проекте** под запросом разрешения: правило хранится у бота по папке проекта и переживает переподключения и перезапуски; в карточке строка «📌 без вопросов в проекте» и экран «📌 Правила проекта» с ❌.
- **⚡ Быстрые команды:** `/macro add <кнопка> | <текст>`, `/macro del <n>`; кнопки в «/menu → ⚡» и в карточке сессии отправляют текст сессии чата (и показывают его в чате).
- **📡 Внешние события (этап 8):** `POST /event` и `bewitched event --topic|--project … [--source …] [--no-deliver]` — сообщение в топик проекта и сессии проекта. **CI:** раз в `CI_WATCH_MIN` (5) минут последний прогон GitHub Actions ветки каждой проектной сессии (через `gh`); упал — «❌ CI упал» с «🛠 Починить» (передаёт сессии задачу с `gh run view --log-failed`), позеленел после красного — «✅».
- **👥 Доли лимита:** в `/usage` — кто сколько занял окна «5 часов» (оценка по стоимости в ценах API); владельцу — уведомление, когда другой пользователь занял больше `USER_SHARE_ALERT` (40%), раз за окно.
- **🌙 Тихие часы** (`QUIET_HOURS` или кнопки в «/menu → ⚙️»): всё, что бот шлёт в эти часы, приходит без звука; ничего не задерживается.
- **Голос:** выбор голоса Silero и скорости (×0.8–×1.5) для каждого чата; даты читаются словами («двадцать девятое октября две тысячи двадцать шестого года»).
- **🌍 Интерфейс на 6 языках** (FR-5): русский, английский, испанский, китайский, французский, немецкий — меню, карточки, уведомления, отчёты, кнопки, ошибки. Язык чата — `/lang ru|en|es|zh|fr|de|auto` или флаги в «/menu → ⚙️»; по умолчанию в личке — язык Telegram пользователя, иначе `BOT_LANGUAGE` (ru). Прогресс, «Готово», напоминания, сторож и CI пишут на языке чата, куда отправляют; меню команд Telegram — на языке приложения. README на всех пяти языках. Тест проверяет полноту словарей.
- `/remind` понимает и английский: «in 2 hours», «tomorrow 9:00», «every day 9:00».
- Документация: README, ТЗ (этапы 0–9 ✅), voice.md — актуализированы.

## 1.2.0 — 2026-10-29

- **Голос читает цифры и латиницу:** Silero понимает только кириллицу и пропускал их. Перед синтезом числа становятся словами (77, 23:16, 41%, 3.5, #36, 1.1.1, 1 600), латиница — кириллицей: словарь частых слов (Claude, Telegram, GitHub, tmux…), аббревиатуры по буквам (PR → пи-ар, CPU → си-пи-ю), остальное — по правилам английского чтения. Для облачных TTS текст не меняется.
- **`/menu`** — одно сообщение-хаб: 📋 Сессии, 📂 Топики, 📊 Статистика (лимиты и расход, итоги дня, отчёты, сервер), 👥 Люди (пользователи, приглашение, разрешения), ⏰ Напоминания, ⚙️ Настройки чата (подробность, «готово», голос, расшифровка — переключателями), ❓ Помощь; у каждого раздела «« Меню». В меню команд Telegram остались `/menu`, `/sessions`, `/usage`, `/help`; остальные команды работают как раньше. `/help` — короткая справка с кнопкой меню.
- **`/server`** (личка владельца): сервер бота и Claude Code — CPU сейчас (за 1 с) и нагрузка 1/5/15, память и swap, диски, процессы Claude Code и сессии, сервисы голоса и демон, топ-5 по CPU и памяти (без аргументов командной строки), кнопка 🔄.
- **Сброс лимита минута в минуту:** когда окно перешло порог `LIMIT_ALERTS`, демон ставит таймер на `resets_at` и пишет «✅ Токены обновились: лимит «5 часов» сброшен, можно пользоваться» (раньше — до 10 мин позже). В `/usage` — «🔔 Напомнить о сбросе» и «🔕 Тихо» (беззвучное сообщение) для любого окна; запросы переживают перезапуск. Полоски лимитов — 20 делений по 5%.
- STT-сервер падал на новых версиях PyAV (`metadata_errors`): WAV от демона теперь декодируется без PyAV. Жадное декодирование по умолчанию (`STT_BEAM`, 1), замеры скорости по моделям в `docs/voice.md`.
- **🎤 Расшифровка голосовых (этап 6):** голосовые, аудио и кружки расшифровываются до того, как попадут к Claude (`🎤 …` + `voice_transcribed`, `voice_language`, …); провайдер `openai-compatible` с цепочкой адресов; локальный faster-whisper как дочерний сервис демона с прогревом модели; `/transcript on|off`; при ошибке — исходное поведение с `stt_error`.
- **🔊 Ответы голосом (этап 7):** `reply_voice`, `voice: true` у `reply`, `/voice off|mirror|always` (по умолчанию — голосом на голосовое); Silero (локальный сервис, поднимается по требованию), Piper, любой OpenAI-совместимый TTS; очистка markdown/кода/ссылок, OGG/Opus через ffmpeg, кэш, текст при ошибке синтеза.
- `bewitched voice install [stt|tts]` — venv, модели, проверка, `.env`. Документация: `docs/voice.md`.
- ТЗ: отличия реализации STT/TTS, FR-5 — перевод на 5 языков.
- Кнопки с длинными подписями (имя пользователя + статус) обрезались посреди эмодзи, и Telegram отклонял сообщение («button text must be encoded in UTF-8»): `/sessions` не открывался. Подписи режутся по целым символам (`clip`), `button()` страхует до 64.
- Пользователи везде (карточки и список сессий, /usage, отчёты, итоги дня, сторож, /users, приглашение) подписаны полным именем, @username, если он есть, и id: «Денис Келин (@deniskelin, 140211098)». Профиль обновляется с каждым сообщением, берётся из приглашения, а для уже добавленных — через `getChat` при старте.
- **🚫 Удаление пользователя из бота:** «🚫 Удалить пользователя» в карточке его сессии или `/users` (список с 🚫; только владелец). Подтверждение перечисляет пути и размеры; затем снимается доступ, закрывается окно tmux с сессией, удаляются `USERS_DIR/<id>` и транскрипты Claude Code, история лички, очередь, память, напоминания и настройки чата. Вариант «и исключить из группы» — ban+unban, без вечного бана.
- Два демона могли запуститься одновременно (перезапуск руками и автозапуск из сессии в одну секунду): pid-файл создавался пустым, и второй процесс считал его брошенным. Теперь файл появляется атомарно (temp + hard link) уже с pid, свежий файл не перехватывается.
- Новый пользователь в `allowFrom` — откуда бы он ни появился (`/invite`, access-skill, правка файла) — получает папку, запущенную сессию, а владелец — шаги и приглашение для пересылки. При первом запуске новыми считаются те, у кого нет папки в `USERS_DIR`.
- Отчёт с долей «<1%» падал на разборе HTML.
- Инструкции канала: команды, пути и id — в `коде`, чтобы копировались нажатием.
- Сессия пользователя называется `claude-<telegram id>` вместо `claude-<username>`: username может отсутствовать или смениться.
- **👥 Приглашение из бота:** `/invite` или кнопка в `/sessions` (только владелец, в личке) → выбор контакта стандартной кнопкой Telegram → подтверждение с предупреждением о полном доступе → добавление в `allowFrom`, папка и запуск сессии `claude-<telegram id>`, одноразовая ссылка в группу, шаги для владельца (с «👁 Экран» для подтверждения запуска) и готовое приглашение для пересылки.
- **📊 Отчёты за сутки, неделю и месяц** (`/reports`, каждый включается отдельно, по умолчанию выключены): когда период закончился, владельцу приходит график расхода (по часам / дням / неделям; SVG → PNG локально через resvg) и статистика — итог и изменение к прошлому периоду, ответы модели, активные часы/дни и пик, модели, сессии с коммитами, доля кэша, лимиты. Кнопки «📨» присылают отчёт за прошлый период сразу. Кэш транскриптов теперь держит 64 дня.
- **⏰ Напоминания и отложенные задачи:** `/remind <когда> <текст>` (30m, 1h30m, «через 2 часа», 18:30, «завтра 9:00», «каждый день 9:00») и `/reminders` со списком и 🗑. В срок текст появляется в чате и приходит сессии этого чата (`event="reminder"`), а если она не запущена — запускает её. Инструмент `remind` даёт сессии самой поставить себе задачу на потом.
- **Разрешения:** кнопка «♾ Всегда <инструмент> в этой сессии»: дальнейшие запросы этого инструмента одобряются без вопроса, пока сессия не переподключится; в карточке строка «♾ без вопросов» и кнопка сброса. `/permissions` и кнопка в `/sessions` — все ждущие запросы по всем сессиям с ✅/❌.
- **`/topics` как меню:** список рабочих топиков с состоянием (сессия, 💤 без сессии, очередь) и кнопкой на каждый, отдельно архив. Экран топика: 💬 Открыть, 📋 карточка сессии, 🚀 Запустить сессию, 🗄 В архив / ↩️ Восстановить, 🗑 Удалить (подтверждение на месте). Строка 🔧 и полные карточки остались только в `/sessions`.
- **💸 Стоимость и итоги дня:** в карточке сессии расход за сегодня в ценах API. В `DIGEST_AT` (21:00, `off` — выкл.) владельцу приходят «🌙 Итоги дня»: расход по сессиям, коммиты за день по проектам (без merge), лимиты. По запросу — `/digest`.
- **🌿 Git в карточке сессии:** `git status -sb`, последние 5 коммитов, PR ветки (через `gh`, если он установлен и авторизован) и «📄 diff файлом» (`git diff HEAD`, секреты маскируются).
- **Управление сессией:** в карточке `/sessions` кнопки 🧹 `/compact`, 🆕 `/clear` (с подтверждением) и 🧠 Модель (opus/sonnet/haiku/fable → `/model <id>`). Команды набираются в окне tmux и только между ходами. Когда контекст переходит `CONTEXT_WARN_PCT` (80%), в чат сессии приходит предложение сжать с кнопкой `/compact`, один раз за заполнение.
- **Уведомления о лимитах:** раз в `LIMIT_CHECK_MIN` минут (10) демон проверяет лимиты подписки и пишет владельцу, когда лимит перешёл порог `LIMIT_ALERTS` (`80,95`; `off` — выключить), и «✅ восстановился» после сброса окна. В закреплённой сводке General строка «📊 5 часов 42% · Неделя 31%».
- **👁 Экран и клавиши:** в карточке сессии и в сообщениях о запуске кнопка «👁 Экран и клавиши» показывает окно tmux и даёт нажать 1/2/3, Enter, Esc, ↑/↓, Tab. Экран подтверждения каналов принимается прямо из Telegram. `SCREEN_REDRAW_MS` — пауза перед повторным снимком.
