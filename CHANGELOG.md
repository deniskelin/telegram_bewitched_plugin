# Changelog

## Unreleased

- **Перезапуск демона посреди хода больше не оставляет «⏳ Работаю…» с ⏹ навсегда.** Демон запоминает открытые сообщения прогресса; при старте те, что остались от прежнего демона, теряют ⏹ и получают строку «⚪️ Прогресс прервался: демон перезапускался. Ответ придёт отдельным сообщением.» Сессия при этом продолжает работать.

- **Codex надёжно получает сообщения.** Раньше демон печатал сообщение в окно Codex посимвольно. Длинный текст Codex сворачивал в «[Pasted Content N chars]»; проверка не находила своего текста и не нажимала Enter, так что сообщение оставалось в поле ввода неотправленным (2026-11-02: первое сообщение в топике пролежало так 21 минуту, а в личке так и не ушло).
  - Теперь текст уходит в окно **одной вставкой** (`tmux load-buffer` + `paste-buffer -p`, через приватный файл: `set-buffer` не принимает длинный текст). Переносы строк сохраняются и не отправляют сообщение раньше времени. «[Pasted Content N chars]» с точным N засчитывается как подтверждение, что текст на месте.
  - Сообщения в одну сессию идут **по очереди** (раньше две вставки могли смешаться). Только что запущенному Codex демон даёт до 30 с, чтобы появилась строка ввода.
  - Если Codex всё же не принял ввод, чат больше не висит на «⏳ Работаю…»: приходит «⚠️ Сообщение не дошло до Codex» с экраном и клавишами (⏎ отправит текст, который уже в поле ввода).
  - **Пауза из-за лимита Claude не держит сообщения для Codex**, а прерванный ход Claude не передаётся Codex с просьбой «доведи до конца».
- **Смена движка и модели в одно нажатие.** В 🧠 после выбора другого движка первой стоит кнопка «♻️ Переключить на Codex сейчас». Сессия закрывается, её окно тоже, и она сразу стартует на новом движке. Экран запуска Claude подтверждается сам (кнопку нажал владелец), а сообщение меню показывает шаги до «✅ Сессия #… работает на Codex». Разговор продолжается: на том же движке тот же, при возврате на прежний движок его последний разговор в этой папке. Codex меняет модель только перезапуском, поэтому после выбора модели сразу предлагается «♻️ Перезапустить сейчас» с тем же разговором.
- **Окна tmux называются по движку:** `codex-user-<id>`, `codex-project-<папка>` (у Claude — `claude-…`, как раньше). У каждого движка своя tmux-сессия, и окно всегда `:0`: раньше Codex открывался окном `:1` рядом с оставшимся окном Claude. Окно закрытой сессии демон закрывает сам.
- **Автоподъём после простоя.** Сессия, приостановленная по сроку бездействия (💤), больше никого не беспокоит. В журнал («🖥 Сессии», ботлог) уходит одна строка «💤 приостановлена… следующее сообщение поднимет её само»; в топике и в личке пользователя ничего нет, в том числе «⚪️ Сессия отключена». Следующее сообщение поднимает сессию само, с её разговором: экран запуска подтверждается автоматически, карточка «🟢 Сессия подключена» в чат не идёт, а в журнал пишется «🔄 поднимается» и «✅ снова в работе, подключилась за N с». В чат пишу, только если подъём не удался. Автоподъём работает и при `TOPIC_NO_SESSION`, отличном от `launch`.
- **Подробный журнал демона** для разбора таких случаев: каждая доставка в Codex (queue или вставка, число символов, сколько ждали готовности, хвост экрана при отказе), каждый запуск (окно, движок, модель, имя, какой разговор продолжается), пропуск запуска замком, смена движка и модели проекта, регистрация сессии (движок, панель, переподключение, автоподъём), хуки начала и конца хода, разговор, о котором сообщили хуки, решения паузы лимита.

- **Статистика по обоим движкам.** `/usage` и закреплённый «📌 Статус» показывают Codex рядом с Claude. Данные берутся из журналов сессий Codex (`~/.codex/sessions`), запросов к OpenAI демон не делает.
  - **Подписка и лимиты:** «Подписка: Pro · Codex: plus»; окна Codex «5 часов» и «неделя» с процентом и временем сброса — по последнему запросу Codex (время указано). Окно, сброшенное после этого запроса, показывается пустым.
  - **Потребление:** строка «Codex — 5 часов / сутки / 7 дней» в токенах; модели Codex (gpt-6.1-sol…) в разбивке «По моделям», его сессии — в «По сессиям». Цены API для моделей Codex нет, поэтому у них только токены; доли «Кто тратит» по-прежнему считаются по Claude.
- **FR-19: сторожа.**
  - **Вопрос на экране без ответа.** Раз в 20 с демон смотрит экраны сессий. Если вопрос висит две проверки подряд — Codex «Trust this folder?» / «Hooks need review», обновление, забытое меню, — в чат сессии приходит «❓ Сессия ждёт ответа на экране» с экраном и клавишами, один раз на вопрос. Запросы разрешений Claude не дублируются (у них свои кнопки), вопрос, уже показанный после команды из меню, тоже.
  - **Замок запуска держится, пока живо окно запуска**, а не 10 минут. Раньше запуск, ждущий подтверждения, через 10 минут позволял второй — и висели два окна. Повторное сообщение в топик получает «⏳ уже запускается» с кнопками экрана этого окна.
  - **«♻️ Перезапустить» в карточке сессии** (⚙️ Управление): закрыть с проверками `/exit` и запустить снова с тем же разговором.
  - **Здоровье сервера.** Если tmux-сервер сменился (а с ним разом остановились все сессии) или выросло число убийств из-за нехватки памяти (cgroup v2 `memory.events` или `/proc/vmstat`; на старых ядрах — только tmux), владельцу приходит одно уведомление с причиной вместо пачки «остановилась».
- **Прогресс в группе больше не может затереть ответ.** Когда ответ забирает сообщение «⏳ Работаю…» себе, летящая в этот момент правка прогресса проигрывает гонку (`canceled by new edit message request`). Раньше это считалось поломкой rich: прогресс навсегда переходил на простой текст и ещё раз правил то же сообщение старым текстом, то есть мог перезаписать ответ. Теперь проигранная гонка, исчезнувшее сообщение и `Too Many Requests` просто пропускаются, а сообщение, уже отданное ответу, демон больше не трогает.
- **FR-16: Codex CLI — второй движок.** В `/menu` → сессия → 🧠 появился ряд движков **Claude Code · Codex** (если Codex установлен). Проект переключается на Codex и его модели (gpt-6.1-sol, terra, astra, luna); «♻️ Перезапустить на Codex» закрывает сессию и запускает её заново на Codex. Разговор на другой движок не переносится.
  - **Профиль `~/.codex/bewitched.config.toml`.** Демон пишет его при каждом старте: наш MCP-сервер (`reply`, кнопки, файлы, голос — как у Claude), наши хуки и инструкции канала для модели. Сессия запускается как `codex --no-alt-screen -p bewitched [-m модель]`, продолжение — `codex resume`.
  - **Входящие** идут в поток сессии через `codex queue`; до первого хука, пока id потока неизвестен, сообщение набирается в окне одной строкой, с проверкой из FR-14.
  - **Ход работы** приходит через хуки: у Codex они совместимы с Claude (`UserPromptSubmit`, `PreToolUse`, `Stop` с последним сообщением). Демон узнаёт процесс Codex; «нашей» считается только сессия с профилем `bewitched`. Вопросы Codex («Trust this folder?», «Hooks need review», выбор через `›`) распознаются как вопросы.
  - **Наши инструменты без вопросов.** В профиле у MCP-сервера `default_tools_approval_mode = "approve"`: Codex вызывает `reply`, `ask_user` и остальные, не спрашивая «Allow the MCP server to run tool?» на каждый вызов.
  - **Нужен полный пакет Codex** (`codex-package-…tar.gz`: `codex` + `codex-code-mode-host` + `bwrap`), а не одиночный бинарник: без `codex-code-mode-host` Codex не может вызвать ни один инструмент.
  - **При первом запуске** Codex спросит, доверять ли папке и хукам. Ответ даётся один раз: «👁 Экран и клавиши».
- **FR-15: слой движка.** Всё, что было зашито под Claude Code (команда запуска, список моделей, распознавание экрана, папка транскриптов), вынесено в адаптер движка (`src/daemon/engines.ts`). Claude Code — первый адаптер, работает через канал; следующий, Codex, будет работать через TUI (FR-16). У сессии есть поле `engine`, у проекта — сохранённые движок и модель. Все запуски (из топика, 🚀, ♻️, лички пользователя) идут с ними.
  - **«🧠 Модель» запоминается для проекта.** Выбранная модель включается сразу (`/model` в окне, с проверкой ввода) и сохраняется: следующие запуски сессии идут с `--model`. «↩️ Модель по умолчанию CLI» сбрасывает выбор. В карточке сессии: «для проекта: …», если проект запускается на другой модели, чем работает сейчас.
- **FR-14: ввод в окно сессии с проверкой.** Всё, что демон набирает в Claude Code (`/exit` при приостановке и ♻️, `/model`, `/compact`, `/clear`, `/resume` из меню, «⌨️ Набрать»), проходит одну проверку. Если на экране вопрос или меню, демон ничего не набирает: Enter подтвердил бы выбранный пункт (одобрил бы команду, сменил бы модель), а цифры выбрали бы вариант. Иначе он набирает текст и жмёт Enter, только когда видит его в строке ввода `❯`. Если ввод не прошёл, приходит экран сессии с клавишами и «⛔ Не набрал», а `/exit` сразу переходит к Ctrl-C.
- **Сравнение с telegram-ai-agent** (`docs/COMPARE-telegram-ai-agent.md`) и беклог мультимодельности FR-14…FR-20 в ТЗ: слой движка, Codex через TUI, разовый режим и ревью другой моделью, запасной движок при исчерпании лимита, сторожа.

- **FR-11: rich-сообщения как в @RichTextDemoBot.**
  - **Экраны демона** (`/menu` и все его разделы, `/sessions`, `/usage`, `/help`, `/reminders`, `/reports`, `/server`, `/digest`, карточки) уходят rich-сообщением: заголовок, разделитель, разделы, подвал. Если Telegram откажет — прежний HTML. `RICH_SCREENS=off` выключает.
  - **Стриминг в группе:** «⏳ Работаю…» — rich-сообщение, шаги в сворачиваемой цитате, под разделителем растёт ответ с разметкой. В конце это же сообщение становится ответом, без второго сообщения. Настройка чата `/menu → ⚙️`: «✏️ конец: правкой» (по умолчанию, без звука) / «🆕 конец: новым» (как раньше, со звуком).
  - **Стриминг в личке:** черновик с Markdown, шаги — в нативном блоке «thinking».
  - **Ответы Claude:** правила оформления в инструкциях канала — длинный ответ с заголовком, разделителем, разделами и оглавлением на якорях, `<details>` для логов, таблицы для сравнений. Одиночный перенос строки в rich больше не склеивается.
  - **🔢 Расход хода — в самом ответе.** Демон дописывает в ответ хода правкой (без нового сообщения) раскрывающуюся таблицу «🔢 Расход хода»: время, запросы к модели, модели, ввод, вывод, чтение и запись кэша, всего, цена в API. Под ней — серый подвал с итогом. Если ответа одним сообщением нет (кнопки, голос) — как раньше, отдельной тихой строкой.
  - **Входящие rich-сообщения** (например, пересланные из бота) раньше терялись. Теперь они доходят до сессии как Markdown.
  - **`reply(use_last_message)`** ждёт до 2 с, если текст ответа ещё не дошёл из хука, а не падает с «no text written».

- **⏹ больше не оставляет сессию в «работает».** Хвост текста остановленного хода приходил после Escape и снова ставил «working», а прерванный ход не шлёт Stop — статус висел до следующего хода. Теперь после ⏹ ход начинает только новое сообщение или промпт. Каждый стоп пишется в `daemon.log`: сессия, откуда (кнопка, меню, «стоп», нативный стоп черновика), отправлен ли Escape. Нативный стоп черновика находит сессию по черновику (и по топику), а не по первому подходящему чату — в форуме он больше не может остановить сессию из другого топика.

- **Зависшая сессия больше не выглядит работающей.**
  - **Приостановка проверяется.** Раньше демон набирал `/exit` и сразу писал «💤 приостановлена»; если `/exit` попадал в меню, сессия оставалась подключённой (31.10 — на сутки), сообщения уходили в неё, а запуск из топика не срабатывал. Теперь через 20 с без отключения — снимок экрана в `daemon.log`, Ctrl-C дважды, ещё через 20 с — SIGTERM процессу Claude. «💤 приостановлена» — только после реального отключения; если сессия так и не закрылась, владелец получает «⚠️ Не смог приостановить» в журнал.
  - **«Не берёт сообщение».** Если после доставки сообщения 2 мин (`TURN_STUCK_SEC`, 0 — выкл.) нет ни хука, ни записи в транскрипт, чат получает экран сессии и кнопки «👁 Экран и клавиши», «♻️ Перезапустить» (закрыть с теми же проверками и запустить с тем же разговором), «⏹ Стоп». Раньше «⏳ Работаю…» тикало 31 мин.
  - **Вопросы Claude Code после команд из Telegram.** После `/model`, `/clear`, `/compact`, `/resume` и «⌨️ Набрать» демон смотрит экран: если Claude Code спрашивает (например, «Switch model?»), экран приходит с клавишами 1/2/3/Esc. Неотвеченный вопрос держал все сообщения сессии.
  - **Один запуск на проект.** «🚀 Запустить» из уведомления о приостановке и сообщение в топике проекта проходят через один замок: раньше они запускали два окна, и второе висело на подтверждении каналов.
  - В `daemon.log` — каждая доставка сообщения в сессию (`message from <чат> → session <id>`).
- В бэклог (ТЗ): FR-12 — шаблонные rich-экраны демона (копирование, живое время, карточки разрешений, чек-лист плана, эфемерные ответы); FR-13 — оформление ответа ИИ и thinking-блок с эмодзи AI Actions.
