# Надёжный интерфейс: сообщения, остановка, сессии и результаты

## Доставка

Демон сохраняет состояние принятого сообщения отдельно от состояния процесса: «Получено ботом», «Ждёт запуска», «В очереди», «Передано агенту», «Агент начал работу», «Готово», «Не доставлено», «Остановлено».

Для долгих запросов появляется тихая карточка с привязкой к исходному сообщению и кнопкой проверки. Короткий успешно завершённый запрос не оставляет дополнительной карточки. Передача в сокет/очередь CLI **не** считается началом работы: это состояние появляется только после активности агента. Уже завершённое состояние не понижается из-за поздней транспортной операции. Существующий сторож сообщает о слишком долгом отсутствии активности и даёт восстановление.

Идентификаторы и состояния сохраняются в SQLite. Активные записи привязываются к переподключившейся сессии той же папки. Большие данные карточек хранятся 30 дней; лёгкие указатели старых сессий сохраняются отдельно. `DELIVERY_CARDS=off` выключает автоматические карточки, не механизм записи состояний.

## Остановка и очередь

Нажатие ⏹ подтверждается как «Команда остановки отправлена». Статус не становится «свободна» только потому, что tmux принял Escape. Демон проверяет экран: подтверждение требует готового приглашения без признаков продолжающейся работы или завершения через хук. Если доказательства нет, появляется «Остановка не подтверждена»; это не утверждение, что процесс обязательно продолжает вычисления. Новое сообщение отменяет проверку старой остановки, чтобы поздний ответ не менял новый ход.

В карточке сессии есть отдельная «Отменить очередь», доступная владельцу и требующая подтверждения. Она удаляет ожидающие сообщения этой сессии из текстового пакета, обычной очереди, очереди занятого Codex и очереди ожидания лимитов. Другие проекты не затрагиваются. Уже переданное агенту сообщение этим действием отозвать нельзя; для выполняющегося хода нужен ⏹. Предыдущая отмена ещё не отправленного текстового пакета при Stop сохранена.

`STOP_NOTICES=off` выключает отдельное сообщение о результате проверки. При неподтверждённой остановке нельзя заключать, что процесс завершился, только по факту отправки команды.

## Список сессий

Сначала показывается личная сессия владельца (включая незапущенную), затем остальные сессии, которым нужно внимание: разрешение, зависший ход, неподтверждённая остановка или непрочитанный результат. Далее — обычные пользователи и проекты. Одна сессия не дублируется в разных разделах.

Рядом со статусом показывается краткая текущая задача из фактически переданных сообщений. Список проектов/топиков открывается отдельной кнопкой, включая проекты без процесса. Подробные карточки и прежнее управление моделью сохранены.

## Старые кнопки

Демон хранит соответствие старого идентификатора сессии папке проекта. После перезапуска старая кнопка открывает актуальную карточку, **не исполняя** прежнюю разрушительную команду против нового процесса. Если продолжения нет, интерфейс сообщает об отключении и возвращает к списку, где доступны запуск и проекты.

Новые клавиши экрана привязаны к сессии, а не только к номеру панели tmux. Если сессия уже заменилась, старая клавиша не отправляет Enter/Escape в новый процесс. Для старых экранов с видимым идентификатором действует та же проверка. Старые приглашения запуска без идентификатора процесса сохраняют прежнюю проверку стартового вопроса. Не обещается восстановление произвольных кнопок, созданных до появления сохранённых указателей.

## Карточки результата

Длинный ответ, результат с файлом/PR либо явные метаданные `reply.result` создают тихую карточку. Модель может передать `summary`, `checks`, `remaining`, `pr_url`. Проверки не придумываются: карточка показывает только предоставленные сведения. Ссылка PR принимается в формате GitHub pull request.

Кнопки позволяют открыть подробности, получить файлы, повторить все исходные части и вложения по порядку, открыть PR и отметить результат прочитанным. Источник повторной отправки — оригинальные Telegram-сообщения; модель не вызывается и произвольные пути файлов не перечитываются. Повтор ограничен исходным чатом и топиком. Удалённое исходное сообщение может сделать повтор невозможным; ошибка показывается пользователю, уже скопированные части могут остаться в чате.

Непрочитанность в групповом топике общая для результата: это не индивидуальное отслеживание каждого читателя. `RESULT_CARDS=off` отключает автоматические карточки. Новые метаданные доступны подключившемуся заново MCP-клиенту; простые длинные ответы и файлы работают без них.

## Проверки

Регрессии проверяют различие передачи и реального старта, отсутствие регресса фазы, смену сессии, гонку обновления карточки с API, положительное/отрицательное подтверждение остановки, новую задачу во время проверки Stop, порядок сессий, запрет выполнения старой destructive-кнопки и повтор всех частей/вложений без утечки в другой чат или топик.

Изменения настроек и новые механизмы демона применяются после его перезапуска. Инструкции и схема инструмента — после переподключения MCP-клиента/нового запуска сессии.
