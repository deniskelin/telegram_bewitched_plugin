# Сравнение с telegram-ai-agent и путь к мультимодельности

*Отчёт от 2026-11-01. Сравнивались [pavel-molyanov/telegram-ai-agent](https://github.com/pavel-molyanov/telegram-ai-agent) (коммит `99398a1` от 2026-10-21, Python, aiogram, ~20 тыс. строк в `core/`) и наш telegram_bewitched_plugin (`develop`, `794dad1`, Bun/TypeScript, ~10,7 тыс. строк в `src/*.ts` и `src/daemon/`).*

## Коротко

- **Разница в подходе.** Мы встроены в Claude Code как канал: сообщения приходят в сессию через MCP, ход работы — через хуки, ответ модель отправляет инструментом `reply`. telegram-ai-agent работает с агентом снаружи: набирает текст в TUI через tmux (или запускает разовый `claude -p` / `codex exec`), а ответ читает из транскрипта. Поэтому у них есть второй движок, **Codex CLI**, а у нас только Claude Code.
- **Что взять для мультимодельности.** Слой «движка»: у топика есть `engine` и `model`, а к каждому CLI пишется адаптер с одинаковым набором действий — запустить, продолжить, доставить сообщение, прочитать события, распознать модальное окно.
- **Что взять для надёжности, независимо от мультимодельности.** Доставка в TUI с проверкой («набрал → убедился, что текст в поле ввода → только тогда Enter»), сторож модальных окон, сторож OOM и падения tmux-сервера, `/recycle`. Первые два закрыли бы обе вчерашние проблемы: «/exit ушёл в меню» и «Switch model? держит сообщения».
- **Чего у них нет, а у нас есть.** Живой стриминг через хуки и черновики, голос в обе стороны, роли и доступ для нескольких людей, журнал, лимиты и `/usage`, напоминания, ответы демона без модели (FR-9), rich-экраны, 6 языков. Переписывать наше на их архитектуру не нужно. Нужно добавить к нашей архитектуре второй путь доставки.

| Люди | `ALLOWED_USER_IDS`, все равны | Владелец, участники, гости; личные сессии пользователей |

## 2. Что у нас уже лучше (сохранить)

- **Живой ход работы без опроса файлов.** Хуки и `sendRichMessageDraft` с блоком thinking, кнопка ⏹, нативный стоп черновика. У них — опрос транскрипта и редактируемое сообщение с задержкой.
- **Модель сама решает, как ответить:** кнопки `ask_user`, rich, файлы, голос. У них итог формирует бот, а rich включается только для ответов с таблицами.
- **Голос:** локальная расшифровка и синтез речи, зеркалирование голосом. У них только расшифровка через Deepgram.
- **Несколько людей:** роли, пары, личные сессии, запросы владельцу. У них — общий список разрешённых id.
- **Журнал, уведомления, пульт, `/usage` с лимитами и окнами, «нет токенов» с паузой (`outoftokens.ts`), напоминания, FR-9, i18n на 6 языков.**
- **Разрешения:** запрос разрешения от Claude Code приходит кнопками ✅ / ❌ / ♾ / 📌. У них такие запросы обрабатываются вручную через `/tui`.

## 4. Мультимодельная организация работы

### 4.1. Два пути доставки

Claude Code остаётся на **канале**: это лучший опыт (стриминг, кнопки, разрешения), и он уже работает. Для остальных движков добавляется **TUI-путь** по образцу их адаптеров, плюс **разовый путь** для коротких вызовов.

```
                     ┌──────────── Engine adapter ────────────┐
Telegram → демон →   │ channel  (Claude Code: MCP + хуки)       │ → стриминг, кнопки, журнал, /usage
                     │ tui      (Codex, Gemini CLI…: tmux +     │   (общие для всех движков)
                     │           ввод с проверкой + транскрипт) │
                     │ exec     (claude -p / codex exec --json) │
                     └─────────────────────────────────────────┘
```

Единый контракт адаптера (TypeScript, по мотивам `ProviderAdapter`):
- `launch(dir, {model, resume})` / `resume(id)` — команда запуска;
- `deliver(text)` — канал или ввод в TUI с проверкой;
- `events()` — начало хода / шаг / текст / итог / конец хода (из хуков или транскрипта);
- `isPromptReady(screen)`, `isModal(screen)` — для доставки и сторожа;
- `transcript(cwd, id)` — где читать историю, для `/resume` и стоимости хода;
- `limits()` — окно и остаток лимита, если CLI их отдаёт.

Всё, что выше адаптера (стриминг, ⏹, журнал, «не берёт сообщение», FR-9, rich), работает с событиями, а не с конкретным CLI.

### 4.2. Сценарии, ради которых это делается

1. **Движок и модель на топик.** В `/menu → ⚙️` топика: «🧠 Claude Opus · Claude Sonnet · Codex · …». Смена применяется со следующего хода (`--model` при запуске или `/model` с проверкой ввода).
2. **Запасной движок при исчерпании лимита.** У нас уже есть `outoftokens.ts`: он ловит конец лимита и ставит сообщения на паузу. Теперь вместо паузы можно предложить «🔀 Продолжить на Codex до сброса» и передать ему краткое содержание разговора и `git diff`. Лимиты разных подписок перестают блокировать работу.
3. **Второе мнение и ревью.** Кнопка «🔍 Ревью другой моделью» под итогом хода: разовый вызов другого движка с diff и задачей. Его ответ приходит отдельным сообщением с пометкой движка. Перекрёстное ревью ловит ошибки, которые модель не видит в своём коде.
4. **Роли в одном проекте.** План делает одна модель, реализует другая, проверяет третья. Удобнее всего так: подтопики проекта или один топик, где ход передаётся по кнопке «▶️ Передать: реализация → Codex». Каждая роль — свой движок и промпт (фича 10).
5. **Дешёвые топики.** Заметки, задачи, вопросы — разовый режим на дешёвой модели, без постоянного tmux.
6. **Учёт по движкам.** `/usage` и «🔢 Расход хода» с разбивкой по движку и модели. Пульт показывает, у какого движка сколько осталось.

### 4.3. Риски и решения

- **Нет хуков у TUI-движков.** Ход работы появляется с задержкой опроса транскрипта (их опыт: работает, но нужен порядок и контрольные точки). Начать с опроса раз в 1 с и ограничения частоты правок.
- **Модальные окна у каждого CLI свои.** Без проверки ввода (фича 3) это опасно. Делать её раньше всех остальных пунктов, она же нужна Claude.
- **Разрешения.** У Codex свои режимы одобрения. Кнопки разрешений, как у Claude, получатся только там, где CLI отдаёт запрос наружу. Иначе — `/tui`-экран с клавишами (у нас уже есть 👁).
- **Контекст между движками не переносится.** При смене движка передаётся краткое содержание разговора, а не весь транскрипт. Это стоит явно показывать пользователю.
- **Стоимость.** «Ревью другой моделью» на каждый ход быстро дорожает. Вызывать по кнопке, автоматически — только по правилу.
