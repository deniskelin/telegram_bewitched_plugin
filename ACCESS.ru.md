# Telegram — доступ и доставка

🌍 [English](ACCESS.md) · Русский · [Español](ACCESS.es.md) · [中文](ACCESS.zh.md) · [Français](ACCESS.fr.md) · [Deutsch](ACCESS.de.md)

Бот в Telegram доступен всем: любой, кто узнает его имя, может написать ему в личку, и без фильтра эти сообщения шли бы прямо в вашу сессию. Описанная здесь модель доступа решает, кто проходит.

По умолчанию личное сообщение от незнакомого отправителя запускает **сопряжение**: бот отвечает 6-символьным кодом и отбрасывает сообщение. Вы выполняете `/telegram-bewitched:access pair <код>` в сессии Claude Code, чтобы одобрить человека. После этого его сообщения проходят.

Всё состояние хранится в `~/.claude/channels/telegram-bewitched/access.json`. Команды skill `/telegram-bewitched:access` правят этот файл; сервер перечитывает его на каждом входящем сообщении, поэтому изменения действуют без перезапуска. `TELEGRAM_ACCESS_MODE=static` фиксирует конфигурацию на момент запуска (сопряжение в этом режиме недоступно: ему нужна запись во время работы).

## Коротко

| | |
| --- | --- |
| Политика по умолчанию | `pairing` |
| ID отправителя | Числовой ID пользователя (например, `412587349`) |
| Ключ группы | ID супергруппы (отрицательный, начинается с `-100…`) |
| Особенность `ackReaction` | Только фиксированный список эмодзи; остальные молча не работают |
| Файл конфигурации | `~/.claude/channels/telegram-bewitched/access.json` |

## Приглашение из бота

Владелец (первая запись в `allowFrom`) может добавлять людей и без кодов: `/invite` в личке с ботом или «👥 Пригласить» в `/sessions`. Стандартный выбор контакта Telegram возвращает ID человека; после подтверждения бот добавляет его в `allowFrom`, готовит `USERS_DIR/<id>` и запускает его сессию, создаёт одноразовую ссылку в группу топиков (нужно право бота «Приглашать пользователей») и присылает владельцу сообщение для пересылки. Их права зависят от роли (см. ниже). В режиме `static` работает только после перезапуска (файл записывается, а снимок — нет).

Удаление устроено так же: «🚫 Удалить пользователя» в карточке его сессии в `/sessions` или `/users`. После подтверждения со списком того, что будет удалено, бот убирает человека из `allowFrom` (и списков групп), закрывает его окно tmux, удаляет `USERS_DIR/<id>` и транскрипты Claude Code, забывает историю лички, очередь, память, напоминания и настройки; по желанию исключает из группы топиков (ban + unban).

## Роли

У сопряжённых пользователей есть роли. 👑 **владелец** — первая запись в `allowFrom` — может всё. 👤 **участник** (по умолчанию) пишет в сессии, отвечает на кнопки `ask_user` и останавливает ход кнопкой ⏹. 👁 **наблюдатель** только читает: его сообщения и нажатия игнорируются. Одобрение разрешений (запросы приходят только владельцу в личку), пульт, архив, настройки, приглашение и удаление людей — только у владельца. Роли владелец меняет в `/users`; хранятся в `access.json` как `"roles": { "<id>": "member" | "viewer" }`. Сессии видят роль автора (`user_role`) и не дают не-владельцу перекрыть указания владельца.

## Политики для личных сообщений

`dmPolicy` задаёт, что делать с личными сообщениями от тех, кого нет в allowlist.

| Политика | Поведение |
| --- | --- |
| `pairing` (по умолчанию) | Ответить кодом сопряжения, сообщение отбросить. Одобрить: `/telegram-bewitched:access pair <код>`. |
| `allowlist` | Молча отбрасывать, без ответа. Полезно, если имя бота легко угадать и ответы с кодом привлекали бы спам. |
| `disabled` | Отбрасывать всё, включая разрешённых пользователей и группы. |

```
/telegram-bewitched:access policy allowlist
```

## ID пользователей

Telegram различает пользователей по **числовым ID** вроде `412587349`. Имя пользователя (username) необязательно и может меняться, числовой ID — постоянный. В allowlist хранятся числовые ID.

Сопряжение получает ID автоматически. Чтобы узнать его вручную, попросите человека написать [@userinfobot](https://t.me/userinfobot) — тот ответит его ID. Можно и переслать @userinfobot любое сообщение этого человека.

```
/telegram-bewitched:access allow 412587349
/telegram-bewitched:access remove 412587349
```

## Группы

По умолчанию группы выключены. Каждую нужно разрешить отдельно.

```
/telegram-bewitched:access group add -1001654782309
```

ID супергрупп — отрицательные числа с префиксом `-100`, например `-1001654782309`. В интерфейсе Telegram их не видно. Чтобы узнать ID, временно добавьте в группу [@RawDataBot](https://t.me/RawDataBot) (он выдаёт JSON с ID чата) или добавьте своего бота: он пришлёт владельцу ID группы и готовую команду; `/telegram-bewitched:access` тоже показывает группы, сообщения из которых недавно отбрасывались.

При `requireMention: true` (по умолчанию) бот отвечает только на @упоминание или ответ на своё сообщение. `--no-mention` — обрабатывать каждое сообщение, `--allow id1,id2` — ограничить, кто из участников может обращаться к боту.

```
/telegram-bewitched:access group add -1001654782309 --no-mention
/telegram-bewitched:access group add -1001654782309 --allow 412587349,628194073
/telegram-bewitched:access group rm -1001654782309
```

**Группы как проекты.** Разрешённую группу (кроме группы топиков) можно привязать к папке проекта. На её первое сообщение (или когда бота в неё добавили) владельцу в личку приходит карточка: новый проект в `PROJECTS_DIR`, существующая папка или «не проект» (отвечает главная сессия, как раньше). Сообщения привязанной группы идут сессии этого проекта, и она отвечает в группу; запросы разрешений этой сессии приходят только владельцу. Отвязать — «👥 Отвязать группу» в карточке сессии или «/menu → 👥 Группы». Привязка не даёт дополнительных прав: кто может писать, по-прежнему решает этот файл.

**Privacy mode.** По умолчанию у ботов Telegram включён privacy mode: сервер Telegram фильтрует сообщения группы ещё до бота и доставляет только @упоминания и ответы. Это совпадает с `requireMention: true`, поэтому обычно незаметно. Для `--no-mention` privacy mode нужно выключить: напишите [@BotFather](https://t.me/BotFather) `/setprivacy`, выберите бота и нажмите **Disable**. Без этого Telegram не доставит сообщения, что бы ни было в конфигурации.

## Как распознаётся упоминание

В группах с `requireMention: true` бота вызывает любое из:

- структурированное упоминание `@имябота`;
- ответ на одно из сообщений бота;
- совпадение с любым регулярным выражением из `mentionPatterns`.

```
/telegram-bewitched:access set mentionPatterns '["^hey claude\\b", "\\bassistant\\b"]'
```

## Доставка

Исходящее поведение настраивается командой `/telegram-bewitched:access set <ключ> <значение>`.

**`ackReaction`** — реакция на входящее сообщение при получении. Telegram принимает только **фиксированный список** эмодзи для реакций; остальные молча игнорируются. Полный список Bot API:

> 👍 👎 ❤ 🔥 🥰 👏 😁 🤔 🤯 😱 🤬 😢 🎉 🤩 🤮 💩 🙏 👌 🕊 🤡 🥱 🥴 😍 🐳 ❤‍🔥 🌚 🌭 💯 🤣 ⚡ 🍌 🏆 💔 🤨 😐 🍓 🍾 💋 🖕 😈 😴 😭 🤓 👻 👨‍💻 👀 🎃 🙈 😇 😨 🤝 ✍ 🤗 🫡 🎅 🎄 ☃ 💅 🤪 🗿 🆒 💘 🙉 🦄 😘 💊 🙊 😎 👾 🤷‍♂ 🤷 🤷‍♀ 😡

```
/telegram-bewitched:access set ackReaction 👀
/telegram-bewitched:access set ackReaction ""
```

**`replyToMode`** — как отвечать при разбиении длинного ответа на части: `first` (по умолчанию) — ответом на входящее сообщение оформляется только первая часть; `all` — все части; `off` — все части отдельными сообщениями.

**`textChunkLimit`** — порог разбиения. Telegram отклоняет сообщения длиннее 4096 символов.

**`chunkMode`** — способ разбиения: `length` режет точно по порогу, `newline` старается резать по абзацам.

## Справочник команд

| Команда | Действие |
| --- | --- |
| `/telegram-bewitched:access` | Показать состояние: политику, allowlist, ожидающие сопряжения, включённые группы. |
| `/telegram-bewitched:access pair a4f91c` | Одобрить код `a4f91c`. Добавляет отправителя в `allowFrom` и шлёт подтверждение в Telegram. |
| `/telegram-bewitched:access deny a4f91c` | Отклонить ожидающий код. Отправитель не уведомляется. |
| `/telegram-bewitched:access allow 412587349` | Добавить ID пользователя напрямую. |
| `/telegram-bewitched:access remove 412587349` | Убрать из allowlist. |
| `/telegram-bewitched:access policy allowlist` | Задать `dmPolicy`: `pairing`, `allowlist`, `disabled`. |
| `/telegram-bewitched:access group add -1001654782309` | Включить группу. Флаги: `--no-mention` (нужно ещё выключить privacy mode), `--allow id1,id2`. |
| `/telegram-bewitched:access group rm -1001654782309` | Выключить группу. |
| `/telegram-bewitched:access set ackReaction 👀` | Задать ключ: `ackReaction`, `replyToMode`, `textChunkLimit`, `chunkMode`, `mentionPatterns`. |

## Файл конфигурации

`~/.claude/channels/telegram-bewitched/access.json`. Если файла нет, это равносильно политике `pairing` с пустыми списками: первое личное сообщение запускает сопряжение.

```jsonc
{
  // Что делать с личными сообщениями от тех, кого нет в allowFrom.
  "dmPolicy": "pairing",

  // Числовые ID пользователей, которым можно писать в личку.
  "allowFrom": ["412587349"],

  // Группы, где бот активен. Пустой объект — только личка.
  "groups": {
    "-1001654782309": {
      // true: отвечать только на @упоминания и ответы.
      // false требует ещё выключить privacy mode у BotFather.
      "requireMention": true,
      // Кто может обращаться к боту. Пусто — любой участник (с учётом requireMention).
      "allowFrom": []
    }
  },

  // Регулярные выражения без учёта регистра, считающиеся упоминанием.
  "mentionPatterns": ["^hey claude\\b"],

  // Эмодзи из фиксированного списка Telegram. Пустая строка — выключено.
  "ackReaction": "👀",

  // Ответы при разбиении: first | all | off
  "replyToMode": "first",

  // Порог разбиения. Telegram отклоняет > 4096.
  "textChunkLimit": 4096,

  // length — резать по порогу, newline — по абзацам.
  "chunkMode": "newline"
}
```
